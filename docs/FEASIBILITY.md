## 测试缺口与成本控制

现有 Smoke 有 2251 行，最终是约百项组合布尔表达式，涉及地图、任务、生存、载具、UI 等广泛功能，不应当把这些作为自己的新增覆盖。原版仅验证一次发射弹药减少；手枪无限备用弹药的部分检查只是重复计算公式，并未调用真实换弹状态机。缺少换弹中切枪/卸载、快速重复输入、部分弹药补充、冷却跨枪、射线遮挡、同队阻挡、多弹丸伤害精确断言和稳定射程两侧检查。

现有联机脚本固定延时、打印计数和 DONE，没有断言配置/玩家身份/伤害收敛/断连清理。本机看到主机残留玩家与 unknown peer RPC，需进一步用禁用 AI 的受控对局验证，暂不定为已确认根因。

新增测试使用完整生产场景；仅固定随机种子、摆放目标、暂停 AI/玩家输入和手动推进真实 `_process(delta)`，通过对外游戏方法施加动作。前置弹药可设置，动作后只读断言；不在断言前改写结果。

## 退出码问题的边界

直接调用 Smoke/net_host 的失败结果确实会返回 0；这是**真实测试基础设施缺陷**。上游 release workflow 已额外 grep `SMOKE: DONE ok=true`，所以不声称原有云端 release gate 必然漏检。下一步保存受控故障注入、独立补丁和修复后记录；故障注入不算产品 Bug。
