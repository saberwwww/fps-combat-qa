# 上游测试审计

对象：OpenFire `7259140487946532af8310723392cca34a4fb0bb`。基线源码完整保留于子模块；原有脚本不计入32个新增场景。

## 实际已有内容

`tests/smoke.gd` 为2251行单场景长流程。涉及开局/任务/导航、发射弹药减少、伤害UI、hitbox/身体对齐、蹲伏、手雷、地图、载具、团队模式、生存需求、装备、背包、NPC、任务、音频等大量内容。详尽原始注释索引见 `evidence/phase1/upstream-smoke-inventory.txt`。

- 65—84行：一次发射与反馈；伤害信号直接 emit、伤害数字直接调用，不是验证真实射线伤害。
- 403—418行：手枪无限备用在局部字典上重复计算，没有通过真实 reload/process 状态机。
- 498—512行：bot来袭伤害折扣/上限与PvP原伤害，因此本项目不再新增这些规则。
- 1031行附近：合作倒地/救起，非本项目死亡竞赛换弹/复活的交叉范围。
- 1847—1882行：护甲分区、装备和卸枪，不包含换弹正在进行时卸掉最后武器。
- 1884—1923行：槽位填充、交换、移除、空槽切换，不包含共享冷却/换弹中断边界。
- 2243—2244行：布尔汇总后 `get_tree().quit()`。本机 DONE false，退出0。

`net_host.gd` / `net_client.gd`：两个真实进程能够进入同一对局，固定延时后打印 net/world玩家和bot数；没有把数量/权限/名字/HP等纳入断言。主机无客户端分支明确打印FAIL但quit默认0。主机在客户端测量后继续存活16秒，基线可以看到名单1人但世界2人，并伴随向unknown peer发RPC的错误。

`.github/workflows/release.yml` 固定Godot4.6.3，Smoke后 grep `SMOKE: DONE ok=true`，已补充日志结果检查。退出码缺陷是真实问题，但不能推导为该release workflow必然假绿。

## 新增与已有测试的区别

| 范围 | 上游已有 | 本项目新增价值 |
|---|---|---|
| 枪械输入 | 曾发射、弹药减少 | 自动/半自动、冷却临界和跨枪冷却 |
| 换弹 | 无限备用公式片段 | 调用真实状态机，部分补弹、备用不足、阻止输入、重复/中断 |
| 装卸 | 槽位及背包基本行为 | 换弹中卸最后一枪的异常与修复回归 |
| 空槽 | 切空槽不变 | 换弹期间切空/非法槽必须保留换弹状态 |
| 死亡 | 合作救援、掉物等 | DM致死→respawn→生命和有限弹药恢复；死者禁止发射 |
| hitbox | 头部射线探测、视觉对齐 | 实际武器射线到真实bot的精确HP差、腿部、同队遮挡、障碍 |
| 霰弹/射程 | 没有对应精确断言 | 9弹丸一次扣壳、299/301m两侧 |
| 联机 | 两端启动与数量打印 | 两端身份/配置/索引/血量快照及退出清理 |
| 门禁 | 汇总日志grep | 子进程超时、脚本异常、严格报告ID、JUnit与故障注入 |

基本枪械/空槽是交叉测试的共同前提，未把上游场景复制过来计算数量。本项目不扩写地图、AI故事、载具或Web平台。D01四个枪械数据点合计一个场景；N02同时比较多个身份属性仍算一个场景；W08重复20次输入也只算一个场景。

## 运行环境差异

固定Godot4.6 stable而非上游release的4.6.3；只在运行副本省略缺失原生库的可选manifest，专用QA用户目录。上游跟踪内容保持干净。原始Smoke中fire_works=false可能与AI击杀静止测试玩家等时序有关，此处没有证明其根因，也未改预期来使它通过。主菜单ComfyUI gate与README“opt-in”式注释存在偏差，以真实代码为准。
